# Protocolo de verificación de tablas mediante navegación y scroll

Activar cuando falta la posición de un rival, hay varias fases/grupos o las fuentes discrepan. Ejecutar también al pedir “verifica la tabla”. Se aplica a todas las ligas; nunca sustituir un dato ausente por una posición estimada.

1. Consultar API-Football para la liga y temporada del fixture. Elegir la tabla de la fase que figura en `league.round` (Clausura, Apertura, etc.). No mezclar una tabla anual con una fase ni usar tablas solo local/visita. Si no se puede identificar el grupo, mantener pendiente.
2. Abrir la tabla pública en FotMob. Confirmar país, liga, temporada, fase y vista general (“All”). Desplazarse hasta la fila completa del rival; leer posición, nombre, partidos y puntos. Guardar URL, hora con zona y texto de la fila. Si no carga, probar Sofascore, página oficial de la competición o medio deportivo con tabla identificada. No usar un fragmento de buscador como prueba suficiente.
3. Repetir la lectura y el desplazamiento en una segunda fuente de dominio distinto, con la misma temporada y fase. No comparar Apertura con Clausura. Si difieren las posiciones, o el equipo/fase no se identifica, registrar conflicto y mantener pendiente, incluso si ambos números superarían 5.
4. Registrar las lecturas en `data/standings-checks.json`: fixtureId, teamId del rival, leagueId, season, phase, checkedAt ISO con zona y dos sources con name, url HTTPS, rank, row y method=`visual-scroll`. Identificar alias de forma explícita, por ejemplo ADT = Asociación Deportiva Tarma. No registrar una lectura que no se realizó.
5. Ejecutar `python scripts/recheck.py` para aplicar los registros al snapshot sin nuevas consultas; o `python scripts/refresh.py --env RUTA_ENV --days 3` para renovar los datos deportivos. El motor exige coincidencia de fixture, rival, temporada y fase; valida dos dominios y posición coincidente. Evidencias de más de 24 horas dejan de servir como respaldo. Si API y web discrepan, se conserva el conflicto.
6. Publicar el snapshot y la evidencia. Revisar en el dashboard el puesto, fase, fuentes y hora. Puestos 1–5 descartan al elegido; 6 o inferior permiten continuar los demás criterios, sin garantizar que resulte candidato.

La navegación con scroll es una revisión asistida por una persona o por el agente al ejecutar este protocolo. GitHub Actions no controla un navegador ni hace scraping periódico de FotMob: consume registros vigentes y marca los que necesitan nueva revisión. No superar bloqueos, CAPTCHA o restricciones de acceso; usar otra fuente y dejar constancia. El navegador del visitante tampoco intenta leer otro sitio mediante CORS.
